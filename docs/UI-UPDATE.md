# 导航、个人中心与管理数据优化

## 页面与导航

首页提供乘客、工作人员与管理员登录入口；登录后首页显示当前身份、服务摘要与快捷入口。底部四个入口各自对应独立内容：

| 导航 | 乘客 | 工作人员 | 管理员 |
| --- | --- | --- | --- |
| 首页 | 登录或个人工作台 | 登录或站点工作台 | 登录或管理工作台 |
| 旅程 / 任务 / 管理 | 当前行程与接应进度 | 本站任务列表与详情 | 设施管理、运营概览、服务分析 |
| 帮助 | 使用步骤、可展开常见问题、系统说明 | 相同 | 相同 |
| 我的 | 个人资料、服务记录、常用行程、阅读偏好 | 个人资料、服务记录、阅读偏好 | 个人资料、记录、概览入口、阅读偏好 |

页面使用 URL hash 保存导航，支持刷新和浏览器前进、返回。服务记录详情使用 `#record?task=<id>` 保留所选任务。匿名用户可阅读帮助；访问旅程、个人中心或管理数据时需登录。

## 人物与偏好

乘客林晓、周宁；工作人员陈雨、苏禾、沈航；管理角色为服务管理员。姓名与服务编号为虚构设定，没有新增真实身份或手机信息收集。业务页面移除重复的数据性质角标，系统范围与数据来源集中在帮助中心的“关于 Route Rescue”说明中。

大字模式、高对比度、常用需求和常用行程按账号保存在当前设备的浏览器存储中；这些偏好不会同步到其他设备。任务和服务进度继续存储于同一服务端数据库。

## 两个管理数据页面

- **运营概览**：近 7、14、30 天服务请求、已完成、与上一等长周期的数量变化、当前处理中及待接单、完成率、趋势图、超过 2 分钟未接单、待交接和设施状态。
- **服务分析**：首次接单平均等待、已确认完成的平均服务用时、跨站交接与归档数量、每日明细、阶段分布、站点发起/交接/完成与通行需求分布。

`GET /api/insights?days=7|14|30` 仅管理员可用，匿名返回 401，乘客和工作人员返回 403。接口只返回聚合信息，不返回乘客账号、备注或个人身份字段。没有新增数据库迁移。

按北京时间请求创建日期分组，包含归档任务。每日完成数是同批创建请求的当前结果，而不是按完成日期计数；当前处理中统计当前未归档任务。平均等待取最早接单事件，服务时长取乘客最终确认事件，没有有效样本显示“—”。当前日期尚未结束，跨期比较会受到部分日期影响。页面每 15 秒刷新统计，用户可手动刷新。数据全部由真实保存的竞赛展示操作汇总，不填充虚假的历史数值。
