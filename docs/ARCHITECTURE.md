# 代码结构

## 页面和应用状态

`frontend/main.tsx` 根据 `/passenger`、`/staff`、`/admin` 选择初始身份。`App.tsx` 负责应用外框、导航和对话框，将具体页面交给 `features/`。

`hooks/useWorkspace.ts` 协调登录会话、页面选择、表单草稿和共享任务同步。页面接收类型化的 `Workspace`，通过明确的命令执行提交、接单、交接或重置，不直接读写数据库。

`services/client.ts` 统一处理 JSON、超时、错误和返回类型。`components/` 放可复用的卡片、按钮、Figma图标、任务摘要和时间线。`features/` 中的模块只负责对应角色或功能的展示与交互。

提交操作使用同步锁，避免 React 更新状态前重复点击发出多个写请求。后台静默同步只保留一个进行中的请求，避免慢网络下每次轮询都覆盖前一次结果。主动操作后的刷新仍可更新当前快照，场景版本用于识别跨设备重置。

## 业务规则

`shared/model.ts` 保存账号、站点、任务类型、数据访问规则与状态流转。服务器调用同一套规则验证操作；前端按钮的显示条件仅用于交互提示。

主要流程：等待接单 → 已接单 → 赶往现场 → 现场接应 → 等待跨站接收 → 已接收 → 等待乘客确认 → 已完成。

工作人员只能按站点与阶段访问任务。源站发起交接后目标站才获得访问权限；目标站确认完成后仍需乘客确认。任务版本号和条件更新防止并发操作互相覆盖。

`shared/insights.ts` 是无数据库依赖的汇总函数。实际记录与历史运营档案使用同一统计口径；档案由 `shared/operations-archive.ts` 提供，不会写入当前任务队列。

## 服务端

`server/index.ts` 是唯一HTTP入口，生产环境服务构建后的前端，开发环境挂载 Vite。`server/router.ts` 按请求方法和接口名分发到 `routes/`，集中转换业务错误。

| 路由模块      | 职责                             |
| ------------- | -------------------------------- |
| `auth.ts`     | 登录、退出、失败频率限制         |
| `scene.ts`    | 角色过滤后的快照、共享场景重置   |
| `tasks.ts`    | 创建任务、状态流转、乐观并发控制 |
| `insights.ts` | 管理员数据范围与聚合统计         |
| `admin.ts`    | 设施变更及兼容的归档操作         |

`core/` 提供请求校验、会话、设施初始化和运行配置；`storage/` 提供统一的参数化查询接口。SQLite事务和云端RPC批次均保证任务与事件一致写入。

## 整理边界

整理版保留正式站V4的交互与接口语义，移出未使用的组件模板、早期框架入口、重复构建方案和本机发布记录。图片与原设计的映射单独保存在 `frontend/assets/`，不依赖在线Figma资源。

发布凭据、私有密码、真实数据库、缓存和依赖目录不属于源码包。维护者可通过锁文件重建依赖，通过 `.env.example` 了解配置项。
