# Route Rescue Windows 离线运行版

本运行包用于赛事现场或评委独立体验，包含 Node.js 24.19.0（Windows x64）、已构建的前端与服务端、全部设计素材、SQLite 数据库引擎及数据库迁移。运行时不需要 npm、联网、ChatGPT 账号或云数据库。需要 Windows 10/11 64 位（x64）与现代浏览器，例如 Edge、Chrome。macOS、Linux、32 位 Windows 不能直接运行本包中的 node.exe；可使用源码中的独立部署说明。

## 三步启动

1. 把整个 ZIP 完整解压到一个可以写入的文件夹，例如桌面或 D 盘。不要只复制启动文件，不要直接在压缩包中运行。
2. 双击根目录的 **启动 Route Rescue.cmd**。浏览器会自动打开乘客端；如果没有自动打开，把黑色窗口中显示的网址复制到浏览器。通常为 `http://127.0.0.1:3000/passenger`；端口被占用时自动选择后续端口，以窗口实际显示为准。
3. 保留启动窗口。结束演示时在该窗口按 **Enter（回车，也可用 Ctrl+C）**。再次启动会继续使用已有数据库，不会清空记录。浏览器页面关闭不等于停止服务。

首次运行自动创建 `data` 目录，并设置“A站2号电梯故障”演示场景。以后启动不会覆盖设施状态或任务记录。启动本机模式无需管理员权限。重复启动会打开已有服务；切换局域网模式前请先停止原启动窗口。

## 入口与账号

在窗口显示的本机地址后，使用 `/passenger`、`/staff`、`/admin` 分别进入乘客端、工作人员端、演示管理端。

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 乘客 | passenger01 / passenger02 | Route2026! |
| A站工作人员 | staffA | Route2026! |
| B站工作人员 | staffB | Route2026! |
| C站工作人员 | staffC | Route2026! |
| 演示管理员 | admin | 首次启动随机生成，见 `data/入口与管理员账号.txt` |

同一浏览器的标签页共享登录状态。双角色演示请分别用 Edge 与 Chrome，或一个普通窗口与一个独立无痕窗口。不同浏览器或设备登录同一账号，读取的是这台运行电脑上的同一数据库。

## 5 分钟演示

1. passenger01 登录乘客端，查看设施故障，选择“下一站下车”，确认位置与需求，发送求助。
2. staffA 登录工作人员端，接单、勾选准备项、前往会合点并确认到场，然后发送交接至 B站。
3. staffB 登录，在“待交接”确认接收，再确认服务完成。
4. 乘客确认完成后任务结束。刷新页面或停止后重新启动，服务记录仍在。
5. 管理员在 `/admin` 可设置故障；输入 RESET 重置场景。重置将任务归档并恢复设施正常；若要重演故障，请再把 A站2号电梯设为故障。

超过2分钟无人接单会展示对应状态，可取消或发起系统内人工关注。所有站点、设施、时间、位置和个人资料均为模拟。没有接入真实地铁接口、室内定位、车辆调度、电话、短信或控制中心。本离线包与线上网站是独立数据库，数据不会自动互相同步。

## 手机与电脑共同演示

1. 停止当前启动窗口，然后双击 **局域网启动.cmd**。
2. 手机与运行电脑连接同一 Wi-Fi，或让电脑连接手机热点。按窗口显示的“局域网候选地址”访问，例如 `http://192.168.1.20:3000/passenger`。工作人员仍可在电脑打开 `/staff`。
3. 使用电脑实际连接的网卡地址，手机不能使用 `127.0.0.1`。如果 Windows 防火墙弹出提示，仅允许当前可信的专用网络；本包不会修改系统防火墙。
4. 网络须允许设备互访。有些校园、酒店、比赛 Wi-Fi 开启客户端隔离，会阻止局域网互访；可改用同一手机热点或路由器。本机离线演示不受此限制。

局域网模式默认监听 `0.0.0.0`，本机模式仅监听 `127.0.0.1`。只有持续运行的同一服务才能共享任务。把文件夹复制到另一台电脑分别启动，会形成两套独立数据库。本包的 HTTP 局域网模式适用于可信演示网络；公网部署请按源码的 SELF-HOST.md 配置 HTTPS。

## 数据、备份与排错

- `data/route-rescue.sqlite`：任务、设施、会话、事件与审计数据；运行时可能同时有 `-wal`、`-shm` 文件。
- `data/local-config.json`：本包管理员密码与初始化标记，不要删除或公开上传。
- `data/入口与管理员账号.txt`：当前入口与本包管理员凭据。
- `data/startup.log`：启动日志，不记录密码。
- 备份：先按 Enter（回车）停服，再完整复制整个 `data` 文件夹。换电脑时连同它一起复制可延续数据与管理员账号。
- 页面打不开：确认启动窗口仍在，使用窗口实际端口，确认整个压缩包已完整解压。不要直接双击 `index.html`，它需要随包提供的本地服务。
- 启动失败：查看窗口错误与 `data/startup.log`。文件夹须可写；运行环境须为 Windows x64。

无需删除数据库来重置演示。请使用受密码保护的 `/admin` 重置入口，保留服务与审计记录。转交他人前可从原始 ZIP 重新解压一份全新运行包，避免把自己的演示记录和管理员配置一起转交。

## 文件说明与源码

`runtime/node.exe` 是随包提供的运行环境；`dist-standalone` 是已构建界面、全部素材与服务端；`server` 是 HTTP 入口；`drizzle` 是数据库结构；`launcher.mjs` 是启动与首次场景初始化程序。`源码/route-rescue-source.zip` 包含完整项目源码、测试和开发运行说明。源码开发构建需要安装其 npm 依赖；日常启动本运行包不需要这些开发依赖。

Node.js 许可证与其第三方声明见 `runtime/Node-LICENSE.txt`。`SHA256SUMS.txt` 可用于校验原始交付文件。可选在 PowerShell 中执行 `Get-FileHash -Algorithm SHA256 文件名` 核对；正常运行不需要执行校验命令。

本包提供可独立运行的现场交付方式。`127.0.0.1` 和局域网地址不属于公网网址；评委远程体验需收到并解压该包，或者由维护者另行部署到可访问的国内服务器。
